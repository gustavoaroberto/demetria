Design target

Accessibility

Demetria targets accessible foundations and WCAG 2.2 AA-informed behavior. This is not a claim that every integration—or the project itself—has been formally audited for conformance.

What the renderer provides

  • A native form, grouped step content, labels, and native controls.
  • Descriptions and errors associated through aria-describedby.
  • An announced error summary and focus on the first invalid control.
  • Focus on the new step heading after successful navigation.
  • Native buttons and keyboard submission behavior.
  • Textual required-field indication rather than color alone.

What the host application owns

  • Visible focus styles with sufficient contrast.
  • Page title, landmarks, heading hierarchy, and skip navigation.
  • Readable colors, zoom and reflow behavior, and motion preferences.
  • Meaningful field labels, descriptions, option text, and error context.
  • Focus behavior around full-document navigation and any surrounding dialog.

Use native elements whenever possible. Styling hooks beginning with demetria__ do not replace semantics and may be themed without changing the generated structure.

Recommended testing

  1. Complete every path using only the keyboard.
  2. Trigger errors and verify announcement, association, and focus order.
  3. Test at 200% and 400% zoom and at a narrow viewport.
  4. Test with at least one screen reader and browser combination.
  5. Add automated checks with Playwright and axe-core as a supplement—not a substitute—for manual review.

Known limitations

Messages are English-only and not configurable in v0.1.0. Automated tests cover keyboard navigation and error focus in jsdom, but no formal assistive-technology or WCAG conformance audit has been completed.
